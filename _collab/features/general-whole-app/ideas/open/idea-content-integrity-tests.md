# Automated Content Integrity Tests

## Summary

A Vitest suite that checks the study data rather than the UI: every quiz question has a valid answer id and the right number of correct options for `multi`, every `lo` exists in the chapter objectives, learn `sections` keys match the chapter's section ids, glossary chapter refs exist, and every path in `tracks.js` has a page. This catches broken content before a learner does.

## Why it fits

The repo has no tests, and the content is large and hand-transcribed from PDFs (CTFL quiz 5,300 lines, 6 tracks). The done-task notes say answers were “verified against the official answer key” by hand; nothing stops a later edit from breaking that. `attachLearn` in each `index.js` silently drops learn sections whose id doesn't match.

## Scope

- Add Vitest (fits Vite) and an `npm test` script
- Data schema checks per track, generated by iterating `tracks.js`
- Cross-reference checks: quiz `lo` ↔ `learn.objectives`, learn section keys ↔ chapter `sections[].id`, glossary `chapters` ↔ chapter ids
- Snapshot of question counts per track/exam set, so an accidental deletion fails
- Optional GitHub Action running `npm test && npm run build` on push

## Risks & unknowns

- The first run will probably surface real data inconsistencies, which then need fixing (or allow-listing)
